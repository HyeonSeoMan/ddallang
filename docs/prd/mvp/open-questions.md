### 2.2 사용자 위임에 따른 Claude 결정 (2026-11-07)

## 4. 확장 위험 제안 (구현 범위 아님)

연기된 기능을 MVP에서 구현하지 않되, 데이터 모델이 아래를 막지 않도록 Spec/Plan 단계에서 검토할 것을 제안한다. (POL §11-5)

- 거래 삭제 시 물리 삭제 대신 상태 값으로 보존하면 후속 감사 이력과 정정 거래로 확장하기 쉽다. (C§3.3과 일치)
- 게임 상태를 두 값으로 하드코딩하지 말고 상태 필드로 표현하면 후속 재개·확정 상태를 추가하기 쉽다.
- 방장 권한을 RoomMember의 속성으로 두면 후속 방장 이전을 추가하기 쉽다.
- 정산 결과 저장 여부는 정책이 정하지 않았다(확정·버전 관리 기능만 제외). 저장 여부는 Plan 단계의 기술 결정이며, 후속 확정 버전을 도입할 때 막히지 않도록 검토할 것을 제안한다. 이 항목은 정책 요구가 아니다.
- RoomMember–Participant 연결은 후속에서 도입될 수 있으므로, 두 개체를 독립 식별자로 두고 연결 정보를 별도 관계로 추가할 수 있게 하는 것이 확장에 유리하다.
