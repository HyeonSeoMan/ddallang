# 딸랑 MVP — 사용자 결정이 필요한 사항

- 대상: `prd.md` v0.1.0 (초안)
- 상태: **전부 미결정.** Claude는 어떤 항목도 임의로 확정하지 않았다. 결정이 나면 상위 문서(정책 또는 PRD)에 먼저 기록한 뒤 해당 게이트를 다시 실행한다. (`.agents/governance.md` §4)
- 구분: OQ-001~005는 정책 원문 항목, OQ-006~026은 PRD 작성 중 발견한 항목이다.
- "권장"은 Claude의 제안일 뿐 결정이 아니다. 우선순위의 **필수**는 Spec 착수 전에 결정되어야 한다는 뜻이다.

## C. 확장 위험 제안 (구현 범위 아님)

연기된 기능을 MVP에서 구현하지 않되, 데이터 모델이 아래를 막지 않도록 Spec/Plan 단계에서 검토할 것을 제안한다. (POL §11-5)

- 거래 삭제 시 물리 삭제 대신 상태 값으로 보존하면 후속 감사 이력과 정정 거래로 확장하기 쉽다. (POL-TXN-005와 일치)
- 게임 상태를 두 값으로 하드코딩하지 말고 상태 필드로 표현하면 후속 재개·확정 상태를 추가하기 쉽다.
- 방장 권한을 RoomMember의 속성으로 두면 후속 방장 이전을 추가하기 쉽다.
- 정산 결과 저장 여부는 정책이 정하지 않았다(POL-SET-007은 확정·버전 관리 기능만 제외한다). 저장 여부는 Plan 단계의 기술 결정이며, 후속 확정 버전을 도입할 때 막히지 않도록 검토할 것을 제안한다. 이 항목은 정책 요구가 아니다.
