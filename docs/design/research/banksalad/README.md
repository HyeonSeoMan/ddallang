# 뱅크샐러드 디자인 참고자료 분석

- 작성일: 2026-11-16
- 목적: 딸랑 디자인을 뱅크샐러드 느낌으로 바꾸기 위한 참고자료 수집과 분석
- 성격: 조사 자료. 딸랑의 Policy/PRD/Spec/Plan을 바꾸지 않으며 디자인 승인도 아니다.
- 이미지: `images/` 62장(뱅크샐러드 자료만 남김)과 이미지 보드 `board.html`. 출처 URL은 `sources.tsv`에 있다.
  모든 이미지의 저작권은 원저작자에게 있다. 내부 참고용으로만 쓰며 `.gitignore`로 커밋에서 뺐다.
  다른 작업 트리에서는 이미지가 없으므로 `sources.tsv`의 URL로 다시 받는다.
- 표기: 이미지 근거는 묶음 기호 + 번호로 적는다(예: A 01 = `images/A-현행스토어__01_appstore.jpg`).

## 0. 한 장 정리

**한 문장:** 뱅크샐러드다움은 "회색 바탕 위 흰 카드, 녹색 하나, 가장 큰 글자는 금액"이다. 장식을 빼서 숫자가 먼저 읽히게 한다.

**딸랑에 가져올 것(우선순위순)**

| 순위 | 가져올 것 | 딸랑에서 바뀌는 곳 | 결정 필요 |
|---|---|---|---|
| 1 | 그림자 없는 흰 카드 + 중립 회색 바탕 | `canvas`, `shadows.card`, `shadows.button*` | 없음(토큰 조정) |
| 2 | 강조색을 녹색 하나로 줄이기 | `accent`(노랑)의 버튼 역할 | 노랑을 아이콘·코인 일러스트로 한정할지 |
| 3 | 라벨 → 큰 금액 헤드라인 구조 | 정산 요약·잔액 화면 | 없음 |
| 4 | 문장형 제목 + 금액만 녹색 강조 | 홈·정산 카드 문구 | 문구 톤(해요체) 확정 |
| 5 | 2×2·2열 카드 배열, 날짜 묶음 목록 | 홈·거래 목록 배치 | Spec 화면 구성과 충돌 여부 확인 |
| 6 | 외곽선 없는 납작한 컬러 아이콘 | 아이콘 세트 | 아이콘 출처·제작 방식 |
| 7 | 지출 검정, 수입만 녹색 + `+` | `gain`·`loss` | FD-18 (1) "손실 빨강" 변경(Plan 수준) |

**그대로 가져오면 안 되는 것**

- 뱅크샐러드 녹색(`#0DA46D`) 위 흰 글자는 3.21:1로 딸랑 대비 규칙(4.5:1)에 못 미친다. 글자를 얹는 녹색은 `#00875A`(4.55:1) 수준으로 어둡게 하고, 밝은 녹색은 차트·장식에만 쓴다.
- 로고, 캐릭터, 아이콘 그림 자체는 베끼지 않는다. 규칙(색 제한, 곡률 통일, 외곽선 없음)만 가져온다.

## 2. 핵심 요약: 뱅크샐러드 느낌을 만드는 7가지

1. **흰 카드 + 아주 옅은 회색 바탕.** 바탕 `#F6F7F9`(실측) 위에 흰 카드를 그림자 없이 올리고, 섹션 사이는 회색 간격으로만 나눈다. 테두리와 그림자는 거의 쓰지 않는다.
2. **녹색 한 가지만 강조색으로 쓴다.** 주 버튼, 강조 숫자, 수입, 차트 막대가 모두 같은 녹색(`#0DA46D`~`#00A86C` 실측)이다. 다른 색은 아이콘 안에서만 나온다.
3. **숫자가 주인공.** "김뱅샐님의 순자산"처럼 작은 회색 라벨을 위에 두고, 그 아래에 아주 굵고 큰 금액(48,200,400원)을 놓는다. 화면에서 가장 큰 글자가 항상 금액이다.
4. **문장 속 숫자 하이라이트.** "**평균 72만원**씩 받는 금융 혜택", "1년에 **80만원** 줄일 수 있어요"처럼 굵은 제목 문장 안의 금액만 녹색으로 칠한다. 사용자 이름을 넣어 말을 건다.
5. **벤토(Bento) 카드 배열.** 2×2 혜택 타일, 2열 요약 카드(내 자산 순위 / 노는 돈 비율), 상단 바로가기 아이콘 4개 줄로 홈을 짠다.
6. **아웃라인 없는 컬러 아이콘.** 2026-10 아이콘 2.0에서 700개 넘는 아이콘의 외곽선을 지웠다. 색 수를 제한하고 곡률을 통일한 납작한 면 아이콘이다. ₩ 동전, 얼굴, 음식 같은 친근한 소재를 쓴다.
7. **해요체 + 혜택 중심 문구.** "알아서 자동으로 대출이자 줄이기", "지난달 이때보다 21만원 더 쓰는 중"처럼 결과(금액)를 먼저 말한다.

## 3. 상세 분석

### 3.1 색

| 역할 | 관찰값(실측·근사) | 쓰임 | 근거 이미지 |
|---|---|---|---|
| 화면 바탕 | `#F6F7F9` | 카드 뒤 바탕, 섹션 간격 | A 01~06 |
| 카드 | `#FFFFFF` | 모든 정보 묶음 | A 전체 |
| 보조 타일 | `#F4F5F7` 안팎 | 카드 안 2×2 혜택 타일, 칩, 작은 버튼("분석", "편집") | A 01, 02, 03 |
| 브랜드 녹색 | `#0DA46D`(CTA 픽셀 실측), 양자화 기준 `#00A86C` | 주 버튼, 강조 숫자, 수입 금액, 선택된 월 | A 01, 02, 06 |
| 밝은 녹색·청록 | `#12BA7E`, `#0CC6BA` | 차트 막대, 도넛, 순위 그래프 | A 03 |
| 연한 녹색 | `#E6F6EF` 안팎 | 상태 띠("금리인하 자동 신청 중이에요"), 차트 배경 면 | A 05, 03 |
| 지출 금액 | 본문 검정 | 지출은 빨강이 아니라 검정, 수입만 녹색 + `+` 부호 | A 02 |
| 상태 배지 | 연파랑 바탕 + 파랑 글자 | "심사 중" | A 05 |
| 일러스트 확장색 | Basil(형광 녹색에 노랑을 섞은 녹색), Mustard(어두워질수록 주황으로 Hue Shift), 로고색 Pink·Green·Blue·Sky | 아이콘·일러스트 전용. UI 색으로는 쓰지 않는다 | F 80, 81 |
| 다크 모드 | 바탕 거의 검정(`#1B1C20` 안팎), 카드 한 단계 밝은 회색, CTA 녹색 유지 | 가계부, 예산 | C 44, 46 |

해석: 색을 "뜻"에 묶었다. 녹색은 '돈이 생기거나 아끼는 것', 검정은 중립, 경고색은 거의 안 쓴다. 화면 하나에 녹색이 들어가는 곳이 2~4군데로 적어서 녹색이 곧 시선 순서가 된다.

### 3.2 글자

- 금액 헤드라인: 28~32pt 안팎, 가장 굵은 굵기. 쉼표 단위 숫자 + "원".
- 화면 제목("가계부"): 22~24pt 굵게, 왼쪽 정렬. 큰 제목 바로 옆에 아이콘 버튼(설정·알림·메뉴)을 둔다.
- 카드 제목·문장형 제목: 17~19pt 굵게, 두 줄까지. 금액 부분만 녹색.
- 라벨: 13~14pt 회색. 항상 숫자 위나 왼쪽에 둔다.
- 목록: 제목 16pt 보통 굵기 / 메타 12~13pt 회색 "커피/음료 | 현대카드M"처럼 세로 막대로 구분.
- 숫자는 오른쪽 정렬, 같은 줄의 보조 정보("결제 취소")는 숫자 아래 작은 회색.

### 3.3 배치와 간격

- 화면 좌우 여백 약 20px, 카드끼리 간격 8~12px, 카드 안 여백 20px 안팎.
- 카드 모서리 약 16~20px(390pt 폭 기준), 카드 안 타일은 12~14px, CTA 버튼 12px 안팎.
- 홈 구조(A 01): 로고·알림·메뉴 → 바로가기 아이콘 4개 → 한 줄 유도 카드(내 자산 순위) → 혜택 카드(문장형 제목 + 2×2 타일 + 전폭 녹색 CTA).
- 가계부 구조(A 02): 큰 제목 → 월 이동(‹ 10월 ›) + 지출/수입 요약 → 인사이트 한 줄 + "분석" 버튼 → 예산 줄 → 목록/달력 전환 + 필터 + 검색·추가 → 날짜별 묶음 목록(날짜 줄에 그날 수입/지출 합계).
- 자산분석(A 03): 큰 숫자 카드 + 막대·선 겹친 차트 + 툴팁 → 추이/구성 세그먼트 → 2열 요약 카드.
- 하단 탭(2021 개편 이후): 자산 / 가계부 / 건강 / 금융(매칭·쇼핑) / 전체. 탭 아이콘은 단색 선 아이콘이고 선택 탭만 채움(D 67, C 48).

### 3.5 아이콘·일러스트(아이콘 2.0, 2026-10)

- 외곽선 제거: 작은 크기(16·24px)에서 선이 뭉개지고 데이터보다 아이콘이 눈에 띄던 문제를 A/B 시안으로 확인하고 지웠다(F 77).
- 13가지 조형 규칙 중 공개된 것: 같은 덩어리감으로 시각 보정, 아이콘당 색 수 제한, 곡률 통일, 상태 배지는 본체를 잘라낸 컷아웃, Good은 반짝임·Bad는 세로선 3개, 좌표 정수화, 얇은 선 최소 두께, 외곽 밝기 기준.
- ₩ 동전을 여러 상태 배지와 조합해 한 계열로 쓴다(F 83).
- 목표: "아이콘은 작품이 아니라 데이터로 안내하는 표지판". 아이콘이 금액보다 먼저 보이면 안 된다.

### 3.6 디자인 시스템 운영(BPL, 2020)

- 계층: Element(버튼·아이콘·스위치) → Child → Container → Scene(E 53~55).
- 이름 규칙: `000_CATEGORY/TYPE/NAME`(고유번호_대분류/소분류/형태별 이름)(E 56).
- 모든 화면 요소를 컴포넌트로 만들었고, 재사용률이 5개월 사이 43% → 85%로 올랐다(E 64).
- 도구를 Sketch에서 Figma로 옮겼다.

## 4. 딸랑에 옮길 때의 비교와 주의점

현재 딸랑 토큰(`apps/web/src/ui/tokens.ts`)과 비교했다.

| 항목 | 딸랑 현재 | 뱅크샐러드 | 바꿀 방향(제안) |

| 버튼 | 아래 가장자리 3px + 녹색 번짐 그림자(게임 느낌) | 납작한 채움 | 납작하게 |
| 주 색 | `primary #12804f`(짙은 녹색) | `#0DA46D` 안팎(밝은 녹색) | 아래 대비 문제 참고 |
| 보조 강조 | 딸랑 노랑 `#ffc93c`(코인·정산·입력 버튼) | UI에 노랑 없음. 노랑은 아이콘 안에서만 | 노랑을 아이콘·코인 일러스트로 한정할지 결정 필요 |
| 카드 모서리 | 24px | 16~20px | 조금 줄이기 |
| 손익 색 | `gain` 초록·`loss` 빨강(FD-18 (1)) + 부호(FD-10) | 수입 녹색 + `+`, 지출은 검정 | FD-18 (1) 개정 필요 |
| 글자 크기 | 제목 20 / 본문 16 / 금액 28 | 금액 28~32, 문장형 제목 17~19 | 금액 크기 규칙은 비슷. 문장형 제목 단계 추가 검토 |

주의점(결정이 필요한 항목):

1. **녹색 대비.** 뱅크샐러드 녹색 위 흰 글자 대비는 `#0DA46D` 3.21:1, `#00A86C` 3.08:1로, 딸랑 규칙(모든 글자 쌍 4.5:1, RK-F15, `tokens.test.ts`)을 통과하지 못한다. 대안: (a) 버튼 바탕을 `#00875A`(4.55:1)처럼 한 단계 어둡게, (b) 밝은 녹색은 차트·장식에만 쓰고 글자 바탕에는 쓰지 않기. 대비 기준을 낮추는 방향은 권하지 않는다.
2. **손실을 검정으로 표시할지.** FD-18 (1)의 "손실 빨강"을 바꾸는 Plan 수준 결정이다. 부호(`+`·`−`)는 FD-10 포맷 규칙이라 그대로 둔다.
3. **노랑의 위치.** 딸랑 노랑을 버튼 색에서 빼면 FE-D1~D3에서 정한 역할(U-5 등)이 바뀐다.
4. **범위.** 디자인 변경은 Plan(디자인 v1.1.0) 개정 → 구현 → 검수 순서를 따라야 한다. 이 문서는 그 입력 자료일 뿐이다.
