# 딸랑 MVP 통합 정책

- 기준일: 2026-11-07
- 상태: 사용자 확정 2026-11-07 (PRD v0.5.0이 v1.0.0으로 취급). 정책 파일에 없는 후속 결정 11건은 `docs/prd/mvp/open-questions.md` 2.1절(사용자 결정 9건)과 2.2절(사용자 위임 Claude 결정 2건)에 있다. 이 헤더 외 본문은 바꾸지 않았다
- 원본: https://app.notion.com/p/410436ae094481b1bd2be2349a575570
- 원칙: Notion §12(MVP 범위), §13(OQ-001~026 결정)가 기존 전체 제품 정책보다 MVP 범위에서 우선한다.

## 1. MVP 범위

**포함:** 방 생성·초대 링크 입장, 익명 RoomMember, 참여자 등록·관리, 단건 거래 생성·수정·삭제, 실시간 거래 목록·누적 손익, 진행 중 예상 정산, 게임 종료·최종 정산·복사, 필수 서버 권한·정합성·중복 요청·오류 처리.

**제외:** RoomMember–Participant 연결/해제, 일괄 입력, 정산 확정·버전, 종료 후 정정 거래, 방장 이전·퇴장·초대 링크 재발급, 상세 감사 UI, 자동 종료·재개·접근 만료·삭제, 미저장 초안 자동 복원. 후속 정책은 폐기하지 않는다.

## 2. 방과 신원

- 방 이름: 필수, 1~12자, 한글·영문·숫자·중간 공백만 허용, 앞뒤 공백·특수문자·이모지 불가, 중복 가능 (OQ-006).
- 생성 시 원·점수·칩 등 정산 단위 선택; 이후 변경·환산 불가.
- 생성 브라우저에 익명 RoomMember 신원을 발급하고 서버가 최초 방장으로 지정. 회원가입·비밀번호 없음. 초대 링크로 입장. 동일 브라우저 재접속 시 신원 복원, 신원 분실 시 권한 복구·자동 승계 없음 (OQ-007·023).
- RoomMember와 Participant는 독립 개체이며 MVP에서 연결·해제 기능 없음 (OQ-001).
- 방별 RoomMember 최대 10명, Participant 최대 10명, 거래 최대 1,000건. 초과 요청은 원자적으로 거부하고 입력 보존·초과 항목 안내 (OQ-004).
- RoomMember·Participant 닉네임 각각 1~12자, 한글·영문·숫자·중간 공백 허용. 앞뒤 공백·특수문자·이모지 불허, 같은 방 같은 유형 내 대소문자 무시 중복 금지. 자동 공백 제거·등록 후 이름 변경 없음. 비활성 Participant의 닉네임도 재사용 불가 (OQ-008·010).
- 진행 중 참여자 추가 가능. 방장만 참여자 비활성화·재활성화 가능. 비활성 참여자는 새 거래에 사용 불가. 종료 후 참여자 추가·상태 변경 불가. 종료 후에도 유효 초대 링크로 새 RoomMember 입장·조회 가능 (OQ-005).

## 3. 단건 거래

- 필수: 서로 다른 Participant ID의 지급자·수취자, 금액 1~999,999,999의 정수. 모든 단위에 동일. 사유·라운드는 선택. 오류 시 저장 거부·입력 유지 (OQ-009).
- 진행 중 모든 RoomMember가 거래 생성 가능. 수정·삭제는 작성자 또는 방장만 가능. 수정 필드는 금액·사유·라운드로 제한. 지급자·수취자·ID·작성자·원본 생성 시각 변경 불가. 당사자 오류는 삭제 후 새 거래 생성. 비활성 참여자가 포함된 기존 거래의 허용 필드 수정 가능 (OQ-011·012).
- 삭제 거래는 일반 목록·손익·정산에서 제외하며 최소 감사 데이터 보존. 상세 감사 UI는 후속 (OQ-013). 최초 삭제만 성공, 새로운 반복 삭제는 `이미 삭제된 거래입니다`로 거부 (OQ-014).
- 거래 생성·수정·삭제에 idempotency key 적용. 동일 키·동일 내용 재시도는 최초 결과 재사용; 동일 키·다른 내용은 충돌 거부. 불명확한 네트워크 실패는 동일 키로 수동 재시도, 요청 내용 변경 시 새 키 사용 (OQ-015·026).
- 동시 수정은 서버에서 마지막으로 성공한 저장이 최종값(LWW). 삭제된 거래 수정 불가.

## 4. 목록·손익·실시간

- 누적 손익은 순손익 내림차순, 동률은 참여자 등록 순서.
- 거래 목록은 **원본 서버 생성 시각 내림차순 → 서버 생성 순번 내림차순**. 수정해도 목록 순서 불변. 20건 단위 커서 페이지네이션 권장 (OQ-016).
- 참여자 한 명의 지급·수취 거래 필터는 목록에만 적용. 누적 손익은 언제나 전체 유효 거래 기준. 필터 변경 시 페이지네이션 초기화 (OQ-017).
- 거래 변경, 참여자 추가·활성 상태 변경, 게임 종료·정산 변경을 새로고침 없이 반영. 재연결 시 서버 최신 상태 재조회 (OQ-018).
- 연결 오류 시 오래된 캐시를 최신처럼 표시하지 않고 조회 차단·오류 안내. 현재 작성 중인 입력 유지, 자동 제출 없음.

## 5. 종료·정산·복사

- 방장만 종료 가능. 최초 종료 요청만 성공; 새로운 반복 요청은 `이미 종료된 게임입니다` 거부, 동일 키 재시도는 최초 결과 재사용. 서버에서 동시 요청 원자적 처리 (OQ-020).
- 진행 중에도 전체 유효 거래로 **예상 정산** 제공·실시간 갱신. 종료 후에는 **최종 정산** 표시. 같은 계산 알고리즘 사용 (OQ-024).
- 지급자 순손익 차감·수취자 순손익 가산, 전체 순손익 합계 0. 탐욕 정산은 매칭마다 남은 채무·채권을 갱신하고 **매번 잔액 내림차순 재정렬**, 동률은 참여자 등록 순서. 0 잔액 제외, 정확한 정산 보장. 전역 최소 송금 횟수 보장 없음 (OQ-021·025).
- 정산 항목은 금액 내림차순, 동률은 참여자 등록 순서. 화면·복사 텍스트 순서 일치.
- MVP 복사 상태 문자열은 `게임 종료` 고정. 방 이름·지급자→수취자·금액 포함. 정산 확정 상태·버전 제외 (OQ-002).
- 수동 종료 후 일반 거래 생성·수정·삭제 불가. 자동 종료·재개·접근 만료·삭제는 후속 (OQ-003).

## 6. 지원 환경

- iOS Safari, Android Chrome, 데스크톱 Chrome·Safari·Edge. 모바일 중심 반응형 UI이며 PC에서도 MVP 전체 기능 사용 가능. 한국어 우선 (OQ-022).

## 7. Spec 이관 및 남은 세부 공백

- OQ-019: 실시간 지연 목표 수치·측정 조건·수용 기준.
- OQ-026: 검증 실패와 서버 처리 불명확 상태별 idempotency key 보관·재사용 정책.
- OQ-004: 삭제 거래를 1,000건 한도에 포함하는지.
- OQ-008: 유니코드 정규화·중간 반복 공백 처리.
- OQ-009: 선택 사유·라운드의 길이·형식.
- 동시 거래 저장/게임 종료 순서, 생성 순번 고유성, 최소 지원 브라우저 버전, UX/접근성·테스트 기준.
