## 1. 검증 전제와 한계

1. 통합 정책은 문서 자체에 "통합 초안 / GitHub 반영 전"이라고 적혀 있고 버전이 없다. 이 파일은 메인 체크아웃(`~/Documents/ddallang`)에 untracked 상태로 있었으며, 읽기 위해 이 워크트리의 `docs/policies/`로 복사했다. 아직 커밋하지 않았다. PRD는 이 통합 정책을 "확정 정책"으로 취급해 작성했지만, 정책 문서 자체의 승인·버전 확정은 사용자 확인 사항이다.
2. 통합 정책에는 `POL-*` 같은 항목 ID가 없다. 추적을 위해 이 PRD에서 **인용 앵커**를 정의한다. 정책 ID가 아니라 PRD 내부 인용 표기이며, 통합 정책의 번호가 있는 절과 글머리표의 순서를 그대로 쓴다. 예: `C§2.5`는 통합 정책 §2의 다섯 번째 글머리표(운영 한도)다.
3. 통합 정책의 OQ 번호(OQ-001~026)는 기존 PRD v0.1.0의 `open-questions.md`와 번호·주제가 일치함을 확인했다. 따라서 결정 결과를 같은 번호에 반영한다.

## 4. MVP와 후속 개발의 혼재 점검

1. 통합 정책 §1과 §5.6은 후속 항목을 제외로 명시했다: 일괄 입력, 정산 확정·버전, 종료 후 정정 거래, 방장 이전·강제 퇴장·초대 링크 재발급, 상세 감사 UI, 자동 종료·재개·접근 만료·삭제, 미저장 초안 자동 복원, **RoomMember–Participant 연결/해제**(기존 정책에는 열린 질문이었고 통합 정책에서 제외로 결정).
2. **예상 정산**은 기존 PRD v0.1.0에서는 "정책이 없어 결정 대기"(OQ-024)였고, 통합 정책에서 MVP 포함으로 확정됐다. 정산 확정·버전 없이 같은 알고리즘을 쓰므로 후속 기능(확정 상태)과는 혼재하지 않는다.
3. 통합 정책의 "후속 정책은 폐기하지 않는다"는 기존 정책 §9의 보존 원칙과 같다. PRD는 이 항목들에 FR을 만들지 않고, 부재를 확인하는 수용 기준만 둔다.
4. 혼재로 볼 만한 지점은 C-07(입력 유지 vs 초안 복원 제외) 한 곳이다. 위 해석으로 분리했다.
5. 기술 선택이 정책 안에 섞여 있는지 점검했다. C§3.4의 "idempotency key"와 C§4.2의 "커서 페이지네이션 권장"이 구현 용어다. 전자는 정책 요구(중복 방지 계약)이므로 PRD가 동작으로 기술하고, 후자는 권장이라 PRD가 요구하지 않는다.
