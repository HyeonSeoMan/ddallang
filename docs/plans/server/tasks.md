# 백엔드 Tasks — `ddallang-server` (G3)

- 문서 버전: 0.1.8 (**초안, 두 번째 예외 검수 REVISE 반영, 검수 한도 소진**). 짝 문서: `plan.md`(결정·소유·위험), `ac-matrix.md`(AC 매핑)
- 기준 Spec: S1 v0.2.3, S2 v0.2.2, S3 v0.2.4, S5 v0.2.3, S4 v0.2.0(커밋은 `plan.md` §1.1)
- 표기: `PD-n`은 `plan.md` §2.2의 결정, `RK-n`은 §6의 위험. Spec 절은 `S2 §5.4`처럼 쓴다. "완료 기준"은 Task가 끝났다고 판정하는 조건이며 모두 자동 시험으로 증명한다. 시험 제목은 `[AC-…]` 태그를 쓴다.
- 소유: 공통 기반(F) Task가 해당 기능의 **유일한 구현 위치**다. 다른 Task는 소비만 하고 다시 만들지 않는다(`plan.md` §3).
- 구현은 승인된 G3와 `ddallang-server` 생성 승인 뒤에 시작한다.

## 수행 순서

`BE-F1 → F2 → F8 → F3 → F5 → S1-1 → F4 → F7 → S1-2 … S1-7 → F6 → S2 → S3 → S5(S5-1, S5-6, S5-2, S5-3 …) → S4(S4-1 … S4-7) → Z1` (각 Task의 "선행" 열이 기준이다. `S1-1`은 `Room`·`RoomMember`·`Participant` 테이블을 만들어 F4·F7·F6이 그 위에 쌓인다.)

**묶음 완료의 뜻**: 묶음은 **그 묶음이 소유한 시험**이 통과하면 끝난다. 다른 Spec의 기능이 있어야 하는 횡단 시험은 그 기능이 생기는 Task로 넘기며 아래 "횡단 시험 이관표"가 소유를 정한다. 이관된 시험이 통과하기 전에는 해당 AC를 완료로 세지 않는다(BE-Z1이 확인한다).

## H. 공통 기반 소유·의존 점검

- 같은 기능을 두 Task가 구현하지 않는다: 문자열 검증은 F5만, 오류·라우트는 F3만, 인증은 F4만, 방 잠금·`revision`·통지는 F2·F7만, 멱등은 F6만 구현한다. S1~S4 Task는 이를 호출한다.
- 마이그레이션 소유는 `plan.md` §3 "스키마 소유"를 따른다. 다른 Task가 같은 테이블 마이그레이션을 만들지 않는다.
- `BE-F6`의 선행에 `S1 완료`를 둔 이유: `IdempotencyRecord`가 `Room`·`RoomMember`를 참조하기 때문이다. 시험은 S2에서 한다.
- 스키마 소유에 `StreamLease`(BE-S5-6)를 더했다.
- 시험 Task(`S1-7`, `S2-5~6`, `S3-3`, `S5-3~5`, `S4-4~7`)는 구현 Task와 다른 ID로 분리해 완료 기준을 독립적으로 판정한다.
