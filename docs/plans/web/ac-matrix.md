# 프론트엔드 AC 매핑표 (`apps/web`)

- 문서 버전: 0.1.0 (**G3 초안, Codex 검수 전, 사용자 미승인**). 짝 문서: `plan.md`(§8 검증 전략), `tasks.md`
- **기준은 각 Spec의 §11 추적표**다. 이 표는 백엔드 매핑표(`../server/ac-matrix.md`)에서 구분이 `FE` 또는 `BE+FE`인 행만 옮긴 파생물이며 AC 의미를 바꾸지 않는다. 표와 Spec이 다르면 Spec이 우선하고 이 표를 고친다.
- 대상: 79행 (FE 전용 34, BE+FE 45). 나머지 146개 AC는 서버가 단독으로 증명한다(백엔드 매핑표). PRD의 AC 225개 중 어느 AC가 FE 대상인지는 이 두 표를 합쳐 확인한다(FE 전용 34 + BE+FE 45 + BE 전용 146 = 225).
- "연동" 열: **M** = 모의 서버(`FE-F7`)로 FE 쪽 시험을 끝낼 수 있다. **R** = 모의 서버 시험 뒤에 실제 백엔드와 만나는 점검(`FE-I1`) 또는 화면 측정(`FE-S5-6`)이 통과해야 완료다. R은 15행이다.
- 규칙: 시험 제목에 `[AC-…]` 태그를 붙이고 `FE-F7`의 검사 스크립트가 이 표의 모든 AC에 태그 달린 시험이 있는지 확인한다. 공통 AC가 여러 Task에 걸리면 첫 Task가 주 담당이다.
- "Spec §11 검증" 열은 Spec의 서술을 줄여 옮긴 것이다(150자 초과는 생략 표시). BE+FE 행은 `UI`·`통합` 부분이 FE 몫이며 `API` 부분은 백엔드 매핑표가 증명한다.
