## 1. 한 문장과 세 원칙

**한 문장:** 회색 바탕 위 흰 카드, 초록 하나, 가장 큰 글자는 금액. 장식을 덜어서 누가 얼마인지가 먼저 읽히게 한다.

1. **숫자가 주인공이다.** 금액은 화면에서 가장 크고 굵다. 아이콘·색·그림자는 금액보다 먼저 눈에 띄면 안 된다.
2. **초록은 하나, 뜻은 하나.** 초록은 "주요 행동"과 "이익"에만 쓴다. 다른 색은 아이콘 안이나 경고에만 나온다.
3. **납작하게.** 카드·버튼·헤더의 그림자를 빼고 바탕색 차이와 간격으로만 나눈다. 화면 위에 겹쳐 뜨는 것(확인 대화상자)만 그림자를 갖는다.

| neutral | `paperSubtle #F2F4F6` / `inkMuted #5F6670` | 5.26 | 비활성·게임 종료 배지 |

토큰 이름 대응: 톤 표는 지금 이름을 그대로 쓰고 값만 바꾼다(`infoBg`/`infoText`, `successBg`/`successText`, `warningBg`/`warningText`, `errorBg`/`errorText`, `neutralBg`/`neutralText`; `successBg`=`primarySoft` 값, `successText`=`brandText` 값, `neutralBg`=`paperSubtle` 값, `neutralText`=`inkMuted` 값). `primaryText`·`dangerText`는 `#FFFFFF` 유지, `focus`는 `primary` 값(`#00875A`, 회색 바탕 위 4.25 ≥ 3). 글자 크기 토큰 `amount`(28px)는 `amountInput`(24px)·`amountList`(18px)로 바꾼다. 새 토큰: `primaryPressed`, `brandText`, `brandBright`, `primarySoft`, `coin`, `radii.tile`, `disabledBg`(`#F2F4F6`)·`disabledText`(`#5F6670`).
대비 시험(`tokens.test.ts`의 `textPairs`)은 새 쓰임에 맞춰 바꾼다: `primary`는 글자로 쓰지 않으므로 `["primary","canvas"]` 글자 쌍을 `["brandText","canvas"]`·`["brandText","paper"]`로 옮기고, `["brandText","primarySoft"]`, 톤 표 5쌍, `["disabledText","disabledBg"]`, `["danger","paperSubtle"]`(삭제 알약, 4.95)를 더한다. 비텍스트 쌍에는 DV-21의 선택 테두리 `["primary","primarySoft"]`(4.09)와 오류 테두리 `["danger","primarySoft"]`(4.90)를 더한다. `primary`는 흰 글자 바탕 쌍(`["primaryText","primary"]`)과 비텍스트(포커스 링 3:1)로 시험한다. 쌍을 빼는 것이 아니라 실제 쓰임으로 옮기는 것이다(RV-4). 단, 지우는 토큰이 든 쌍(`["ink","accentSoft"]`, `["secondaryText","secondary"]`, `["accentText","accent"]`)은 토큰과 함께 지운다(쓰임이 사라지므로 시험 약화가 아니다). 비텍스트 쌍 `["line","canvas"]`도 지운다: `line`은 흰 바탕의 입력·선택 상자·타일 경계에만 쓰고 회색 바탕 위에는 쓰지 않는다(새 값 3.0001로 경계에 걸린 쌍을 남겨 두면 값을 조금만 바꿔도 실패하는데, 그 실패가 실제 쓰임을 가리키지 않는다). 대신 `["line","paper"]`를 둔다.
지우는 토큰: `accent`(→ `coin`, 아이콘 안 색으로만), `accentText`, `accentSoft`, `secondary`/`secondaryText`(→ `paperSubtle`/`ink`), `shadows.card`·`button`·`buttonAccent`·`buttonPressed`·`chip`. 아바타 바탕 6색(장식, 글자는 `ink`로 13.7:1 이상): `#DDF3E8`, `#E1ECFF`, `#FFE8D6`, `#F1E4FF`, `#FFE1E6`, `#E5E8EB`.

## 5. 페이지별 적용

구역의 상대 순서, Spec 문구, §7 문구, FD-12 페이지 구성은 그대로다. 바뀌는 것은 모양뿐이다(단, 방 만들기의 정산 단위 선택 방식(선택 상자 → 아이콘 + 글자 라디오 타일, U-18·DV-21)과 지급자·수취자·참여자 필터의 선택 방식(선택 상자 → 칩 라디오, 1.1.0 U-19·DV-17)은 Spec·AC 범위 안의 상호작용 변경이다).

### 5.1 공통 헤더(떠 있는 헤더)

- **화면 폭 전체를 쓰는 막대**, 모서리 0, 위쪽 고정(sticky, 지금처럼 스크롤해도 보임). 바탕은 흰 단색 `#FFFFFF`(반투명·흐림 없음), 구분선·그림자 없음(회색 바탕과의 색 차이로 나눈다, §2.1). 지금의 좌우 여백 둔 둥근 카드·`shadows.float`·고정 래퍼의 그라데이션은 없앤다. **흰 바탕은 뷰포트 폭 전체**(위쪽 안전 영역 `safe-area-inset-top`까지 흰색)이고, 안의 방 이름·탭은 본문과 같은 `md` 열 폭 안에 정렬한다. 왼쪽에 방 이름 20/700, 옆에 진행 상태 배지. 로고 아이콘은 두지 않는다(DV-16).
- 그 아래 탭 4개(종료된 방은 `기록`을 뺀 3개, FD-12)(DV-9). 끊김 중에는 지금처럼 `DDALLANG`만 보인다.
- **끊김·연결 중(서버 유래 영역이 가려질 때):** 연결 배너는 지금 문구 그대로(제목 + 상세) §3.1 톤의 띠로 보인다. 각 구역은 제목 아래 **스켈레톤 카드**를 보인다(DV-23, 1.2.0. 1.1.0까지는 "바탕 위 제목만, 카드·스켈레톤·대체 문구 없음"이었다). 서버 값과 대체 문구는 없다(S5 §6.5). 첫 로딩(스트림이 아직 연결되지 않은 최초 상태)도 같은 모양이다. 재시도하지 않는 접근 불가(401·404, S5 §6.6)에서는 기다려도 값이 오지 않으므로 스켈레톤 없이 바탕 위 제목만 남는다(Q-C7). 데이터가 보이는 동안 게임이 끝나 폼이 없는 거래 입력 구역은 지금처럼 바탕 위 제목만 남는다.
- 흰 헤더가 스크롤 중 흰 카드 위를 지날 때의 경계는 RV-5로 확인한다.

### 5.2 현황(`누적 손익`, `거래 내역`)

- **누적 손익 카드:** 참여자마다 목록 행(DV-11). 오른쪽 금액은 이익 `+` `brandText`, 손실 `−` `ink`, 0은 `ink`(FD-10 부호 그대로). 비활성은 이름 옆 회색 배지. 서버 순서 그대로.
- **거래 내역 카드:** 맨 위에 참여자 필터(DV-17 1.1.0: `참여자 필터` 라벨 → 칩 묶음 → 상태 문단). 행 = 회색 원 안 코인 아이콘(DV-14) · "가온 → 나래"(16/400) + 메타 · 오른쪽 금액(18/700, 부호 없음). **메타는 지금 앱과 같은 항목·순서로 한 줄에 하나씩**: `사유: …`(있을 때), `라운드: …`(있을 때), 시각 `MM/DD HH:mm`. 모두 14/500 `inkMuted`, 사유(최대 50자)는 잘라내지 않고 줄바꿈한다. 작성자는 보이지 않는다(S3 C-2). 수정·삭제는 메타 아래 회색 알약(§4 보조 버튼, 터치 44px)(삭제는 `danger` 글자). `더 보기`는 카드 아래 전폭 회색 버튼. **수정 중인 행**은 행 내용 아래에 카드 폭 전체로 수정 폼(지금 입력 항목·버튼 그대로)이 펼쳐지고, 그동안 오른쪽 금액은 그대로 둔다.
- **`거래 기록하기`:** 화면 아래 고정 전폭 주 버튼 모양의 링크(FD-18 (4) 동작 그대로).

### 5.3 기록(`거래 입력`)

- 한 카드 안에 지급자 → 수취자 선택, 금액 입력(24/700 오른쪽 정렬, 단위 표시). 입력 항목은 지금과 같다(지급자·수취자·금액·사유 (선택)·라운드 (선택)).
- 지급자·수취자는 칩으로 고른다(DV-17 1.1.0). 둘 사이에 `→` 구분선(장식).
- 저장 버튼은 폼 안, 카드 아래 전폭 주 버튼(DV-19). 저장 안내는 폼 카드 맨 위의 success 띠(완료 아이콘 + `거래를 저장했습니다.`)이고, 저장 뒤 폼은 비워진다(U-10, 지금 동작 그대로).

### 5.4 정산(`예상 정산`·`최종 정산`, `게임 종료`)

- 카드 안 순서는 지금 앱 그대로다: 맨 위 배지(예상 = `진행 중` info, 최종 = `게임 종료` neutral) → (예상일 때) 안내 문구 info 띠 → 정산 항목 → (최종일 때) `정산 복사` 버튼과 상태 문단. 배지는 서버 유래라 카드 안에 있어 끊김 중에는 카드와 함께 가려진다.
- 정산 항목은 §4 정산 행(아바타 없음, 구분선). 이체 방향은 아이콘이 아니라 글자(`→`)로 전한다.
- 최종 정산의 `정산 복사`는 항목 아래 카드 폭 회색 전폭 버튼(DV-12)이고, 결과는 그 아래 상태 문단(토스트 아님). 모든 항목은 같은 행(DV-18).
- `게임 종료`는 정산 카드와 구분선으로 떨어뜨린 위험 버튼(테두리형). 확인 대화상자 안에서만 빨강 채움.

### 5.5 방(`방 정보`, `참여자`)

- 방 정보 카드: **지금 문구 그대로** 세로로 쌓는다. 방 이름(20/700, 라벨 없음) → `정산 단위: 원`(16/400) → 진행 상태 배지 → `내 닉네임: 김철수` + 방장 배지. 새 라벨을 더하지 않는다.
- 초대 링크: 보이는 라벨 `초대 링크` + **지금처럼 readOnly 입력란**(포커스하면 전체 선택, §4 입력 규칙, 긴 링크는 입력란 안에서 잘림) + 그 아래 회색 알약 `초대 링크 복사` + 상태 문단 + (진행 중일 때) QR과 안내 문단(DV-22, 1.2.0). 복사 실패 문구("링크를 직접 선택해…")가 입력란 선택에 기대므로 입력란을 없애지 않는다.
- 참여자 카드: 목록 행(DV-11). 방장 컨트롤(비활성화·재활성화)은 행 오른쪽 회색 알약. 행의 오류 문구(`role="alert"`)와 `다시 시도`는 행 내용 아래 카드 폭으로 펼친다(거래 행 수정 폼과 같은 방식). 등록 폼은 목록 아래 구분선 뒤에 `참여자 닉네임` 입력과 **주 버튼** `참여자 등록`(지금처럼 기본 버튼).

### 5.6 방 만들기·초대 입장

- 맨 위 `BrandHeader`: 동전 종 아이콘(장식) + h1 `DDALLANG`(**문구 유지**, 접근 가능한 이름 그대로). 그 아래 흰 카드 하나. 홈은 카드 제목 `방 만들기`(지금 그대로) + 입력 + 아래 전폭 주 버튼. **입장 화면은 지금처럼 카드 제목이 없고**, 카드 안 방 미리보기(`section aria-label="방 정보"`)는 §5.5 방 정보 규칙을 따른다: 방 이름 20/700 → `정산 단위: …` 16/400 → 진행 상태 배지(진행 중 info, 게임 종료 neutral, 지금 success를 info로 통일) → 종료 안내 문단(있을 때, 14/500 `inkMuted`). 그 아래 닉네임 입력·버튼은 지금 구성 그대로. 바탕은 `canvas`. 정산 단위는 아이콘 + 글자 타일 라디오(DV-21). 닉네임 입력 아래 신원 키 안내 문단(지금 문구 그대로, 14/500 `inkMuted`), 그 아래 주 버튼. 글자 `딸랑`으로 바꾸는 것은 문구 변경이라 하지 않는다.
